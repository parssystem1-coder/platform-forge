# ۲. خلاصه تصمیم‌های معماری

جدول مرجع سریع. هر تصمیم ADR کامل در `80-adr/` دارد.

| # | تصمیم | انتخاب | چرا | ADR |
|---|-------|--------|-----|-----|
| ۱ | سبک استقرار | Modular Monolith | مسئله امروز مرز است نه مقیاس. مرز بد را با شبکه نمی‌شود درست کرد. | 0001 |
| ۲ | جداسازی مستاجر | Shared DB + tenant_id + RLS | دفاع در عمق. باگ اپلیکیشن نباید به نشت داده منجر شود. | 0002 |
| ۳ | نشست | JWT کوتاه‌عمر + Refresh مبهم چرخشی | لغو امن و کشف سرقت توکن | 0003 |
| ۴ | مدل دسترسی | یک authorize واحد: Permission + Feature + Quota | چند نقطه تصمیم یعنی رخنه امنیتی | 0004 |
| ۵ | Entitlement و Capability | یکی شدند به نام Feature | دو مفهوم تقریباً یکسان یعنی تناقض TRUE/FALSE | 0004 |
| ۶ | پول | Ledger دوطرفه از روز اول | تطبیق مالی بعداً غیرممکن است | 0005 |
| ۷ | سهمیه | رزرو اتمیک reserve/commit | جلوگیری از مسابقه و فروش اعتبار منفی | 0006 |
| ۸ | رخداد | Transactional Outbox | رخداد گم‌شده یعنی وضعیت ناسازگار | 0007 |
| ۹ | هویت خریدار | realm جدا از کاربر پلتفرم | یکی کردن، فردا مدل دسترسی را می‌شکند | 0008 |
| ۱۰ | مسیر خواندن فروشگاه | Read Model + CDN + ISR | فروشگاه Data Plane است، نه پنل | 0009 |
| ۱۱ | ORM | Drizzle و SQL صریح | کنترل روی SQL و سازگاری با RLS | 0010 |
| ۱۲ | اتوماسیون | Gateway داخلی، n8n اختیاری و دیرتر | n8n چندمستاجری پرریسک‌ترین شرط شخص ثالث | 0011 |
| ۱۳ | AI | AI Gateway اجباری، صدا زدن مستقیم Provider ممنوع | کنترل هزینه، fallback، لاگ، نسخه prompt | 0012 |
| ۱۴ | MCP | بعد از پایداری API و دسترسی | MCP یک Interface است، نه معماری | 0013 |
| ۱۵ | دامنه اختصاصی | مسئله Ops با فاز جدا | صدور SSL در مقیاس و سهمیه CA | 0014 |

## تصمیم‌هایی که عمداً به تأخیر افتادند

| موضوع | شرط ورود |
|-------|----------|
| استخراج Microservice | یک bounded context با درد عملیاتی پایدار که در فرآیند حل نمی‌شود |
| OpenSearch | جستجوی Postgres با ۵۰ هزار محصول در هر Tenant به بودجه latency نرسد |
| Kubernetes | نیاز واقعی به autoscaling چندسرویسی، نه حرفه‌ای به نظر رسیدن |
| Plugin Sandbox | حداقل ۳ افزونه شخص ثالث واقعی |
| Marketplace | حداقل ۵ افزونه و یک مدل درآمد روشن |
| Dedicated Infra | اولین قرارداد Enterprise امضا شده |

## معیار بازبینی معماری

معماری هر سه ماه یا با وقوع هر یک از این‌ها بازبینی می‌شود:

- یک بودجه کارایی به‌طور پایدار نقض شود
- یک ماژول بیش از دو بار مرز ماژول دیگر را بشکند
- تعداد Tenant فعال ۱۰ برابر شود
- یک حادثه امنیتی مربوط به جداسازی رخ دهد
