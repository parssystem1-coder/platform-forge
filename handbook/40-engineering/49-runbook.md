# ۴۹. رانبوک عملیاتی

این فایل برای ساعت ۳ بامداد است، وقتی کسی حوصله‌ی خواندن معماری را ندارد.

## ۴۹.۱ علامت: افزایش خطای 5xx

```text
1. /readyz را چک کن
2. وضعیت اتصال دیتابیس و استخر را ببین
3. لاگ را بر اساس correlationId دنبال کن
4. اگر یک اندپوینت خاص است: آخرین دیپلوی مربوطه را ببین
5. اگر همه اندپوینت‌هاست: دیتابیس یا Redis مشکوک است
6. تصمیم rollback در ۱۰ دقیقه اول
```

## ۴۹.۲ علامت: صف Outbox رشد می‌کند

```text
1. زنده بودن پروسه worker را چک کن
2. جدول خطاها را ببین: SELECT last_error, count(*) ... GROUP BY 1
3. اگر یک نوع رخداد خاص گیر کرده: موقتاً available_at را عقب ببر
4. اگر همه گیر کرده‌اند: مصرف‌کننده یا وابستگی خارجی خراب است
5. هرگز صف را پاک نکن. این داده از دست رفتن است
```

## ۴۹.۳ علامت: مشتری می‌گوید پول دادم ولی سرویس نگرفتم

```text
1. جدول payment_webhook_events را برای آن Tenant ببین
2. اگر webhook نرسیده: job مغایرت‌گیری را دستی اجرا کن
3. اگر رسیده ولی پردازش نشده: خطای پردازش را ببین
4. وضعیت Subscription و Ledger را مقایسه کن
5. اصلاح فقط با entry جدید، هرگز با UPDATE در دفتر
```

## ۴۹.۴ علامت: مشکوک به نشت داده بین مستاجر

این حادثه با اولویت حداکثر تلقی می‌شود:

```text
1. دامنه را مشخص کن: کدام اندپوینت، کدام Tenant
2. لاگ و Audit را برای دسترسی متقابل بررسی کن
3. تأیید کن سیاست RLS روی جدول مربوطه فعال است
4. تأیید کن نقش اپلیکیشن مالک جدول نیست
5. اندپوینت را موقتاً غیرفعال کن، نه اینکه در حال کار دیباگ کنی
6. تست بازتولید بنویس، بعد اصلاح کن
7. گزارش حادثه بنویس
```

## ۴۹.۵ علامت: کندی فروشگاه

```text
1. نرخ cache hit را ببین. اگر پایین است، مشکل باطل‌سازی افراطی است
2. تأخیر پروجکشن Read Model را ببین
3. تعداد query در هر صفحه را چک کن (باید حداکثر ۳ باشد)
4. دنبال N+1 جدید بگرد
```

## ۴۹.۶ رول‌بک

```text
اگر مهاجرت نداشته:      کافی است نسخه قبلی را دیپلوی کنی
اگر مهاجرت expand داشته: رول‌بک کد امن است
اگر مهاجرت contract داشته: رول‌بک خطرناک است، باید forward fix کنی
```

به همین دلیل الگوی دومرحله‌ای اجباری است: به تو اجازه‌ی رول‌بک می‌دهد.

## ۴۹.۷ در حادثه چه چیزی را هرگز انجام نده

- پاک کردن داده برای رفع سریع مشکل
- خاموش کردن RLS برای دیباگ
- UPDATE دستی در جدول دفتر مالی
- دیپلوی بدون ریویو در میان حادثه
- خاموش کردن هشدار به جای حل علت
