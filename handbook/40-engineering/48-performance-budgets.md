# ۴۸. بودجه کارایی

## ۴۸.۱ چرا عدد لازم است

بدون عدد، هر کندی «قابل قبول» به نطر می‌رسد تا روزی که مشتری زنگ بزند.

## ۴۸.۲ بودجه API

| مسیر | p50 | p95 | p99 |
|------|-----|-----|-----|
| `GET /me` | 40ms | 150ms | 300ms |
| `POST /auth/login` | 120ms | 400ms | 700ms |
| `POST /auth/refresh` | 50ms | 200ms | 400ms |
| `GET /products` (پنل) | 80ms | 300ms | 600ms |
| `POST /products` | 100ms | 400ms | 800ms |
| `POST /orders` | 200ms | 800ms | 1500ms |

توجه: `login` عمداً کندتر است چون Argon2id عمداً کند است. این ویژگی امنیتی است، نه باگ.

## ۴۸.۴ بودجه دیتابیس

| معیار | حد |
|-------|-----|
| هر query در مسیر درخواست | زیر 50ms |
| تعداد query در یک درخواست پنل | حداکثر 10 |
| تعداد query در صفحه فروشگاه | حداکثر 3 |
| طول تراکنش | زیر 200ms |
| مصرف استخر اتصال | زیر 70٪ در حالت عادی |

### ممنوعیت قطعی: N+1

هر جایی که در حلقه query می‌زنی، باید در ریویو رد شود.
ابزار: لاگ تعداد query در هر درخواست در محیط توسعه.

## ۴۸.۵ بودجه رخداد و کارهای پس‌زمینه

| معیار | حد |
|-------|-----|
| تأخیر انتشار Outbox (p95) | زیر 2s |
| قدیمی‌ترین رخداد منتشرنشده | زیر 60s (وگرنه هشدار) |
| تأخیر پروجکشن Read Model | زیر 30s |
| تأخیر ارسال ایمیل تراکنشی | زیر 60s |
