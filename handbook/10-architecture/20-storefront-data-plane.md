# ۲۰. مسیر داده‌ی فروشگاه

> این فایل در نسخه اولیه کاملاً غایب بود. مهم‌ترین افزوده‌ی معماری جدید است.

## ۲۰.۱ چرا این مهم است

در یک پلتفرم E-Commerce، تقسیم واقعی ترافیک این است:

```text
پنل ادمین:   ۱٪ درخواست‌ها، ۹۰٪ پیچیدگی منطق
فروشگاه:     ۹۹٪ درخواست‌ها، ۱۰٪ پیچیدگی منطق
```

اگر فروشگاه را با همان الگوی پنل بسازی (تراکنش، RLS، authorize کامل، جوین سنگین)، اولین کمپین تبلیغاتی مشتری سیستم را زمین می‌زند.

---

## ۲۰.۲ تفکیک خواندن و نوشتن

```text
مسیر نوشتن (پنل ادمین)
  Product CRUD -> جدول عملیاتی -> رخداد -> پروجکتور
                                                    |
                                                    v
مسیر خواندن (فروشگاه)                        Read Model
  CDN -> Next.js ISR -> Read Model (دنرمالایز)
```

### Read Model چیست و چه نیست

**هست:** یک جدول دنرمالایز در همان Postgres که هر چیزی که یک صفحه محصول لازم دارد در یک ردیف دارد.

**نیست:** یک دیتابیس جدا، نه Elasticsearch، نه مرجع حقیقت.

```sql
CREATE TABLE storefront_products (
  tenant_id uuid NOT NULL,
  product_id uuid NOT NULL,
  slug citext NOT NULL,
  status text NOT NULL,
  payload jsonb NOT NULL,   -- عنوان، قیمت، تصاویر، ویژگی، دسته، متا
  version bigint NOT NULL,  -- برای تشخیص کهنگی
  updated_at timestamptz NOT NULL,
  PRIMARY KEY (tenant_id, product_id)
);
CREATE UNIQUE INDEX ON storefront_products (tenant_id, slug);
```

یک query بدون join برای یک صفحه کامل. این تفاوت ۳۰۰ms با ۱۵ms است.

---

## ۲۰.۳ لایه‌های کش

```text
۱. CDN edge          ثانیه تا دقیقه، بر اساس stale-while-revalidate
۲. Next.js ISR       نسخه رندرشده صفحه
۳. Redis             داده پرتکرار مشترک (منو، دسته‌ها، تنطیمات فروشگاه)
۴. Read Model        منبع خواندنی
۵. جدول عملیاتی     فقط برای نوشتن و موارد لحظه‌ای
```

### چه چیزی هرگز کش نمی‌شود

- موجودی دقیق در لحظه تکمیل خرید
- سبد خرید
- قیمت نهایی در مرحله پرداخت
- هر چیز مختص به یک خریدار خاص

قاعده: موجودی در صفحه محصول می‌تواند تقریبی باشد (موجود / ناموجود)، ولی در checkout باید دقیق و رزروشده باشد.

---

## ۲۰.۴ باطل‌سازی کش

```text
ProductUpdated (رخداد)
  -> پروجکتور Read Model را به‌روز می‌کند
  -> تگ کش باطل می‌شود: tenant:{id}:product:{slug}
  -> مسیر ISR بازاعتبارسنجی می‌شود
  -> CDN purge هدفمند (نه purge کلی)
```

استراتژی تگ‌گذاری پیشنهادی:

```text
tenant:{tenantId}                 کل فروشگاه (تغییر قالب یا تنطیمات)
tenant:{tenantId}:catalog         تغییر دسته‌ها یا منو
tenant:{tenantId}:product:{slug}  یک محصول
```

> purge کلی به ازای هر تغییر کوچک، یعنی عملاً کش نداری.

---

## ۲۰.۵ رزرو موجودی

همان الگوی سهمیه، ولی روی موجودی:

```sql
UPDATE inventory_items
   SET reserved = reserved + $qty
 WHERE tenant_id = $t AND variant_id = $v
   AND on_hand - reserved - $qty >= 0
RETURNING *;
```

چرخه:

```text
افزودن به سبد       -> بدون رزرو
شروع checkout      -> رزرو با TTL ۱۵ دقیقه
پرداخت موفق        -> قطعی و کاهش on_hand
انصراف یا انقضا    -> رهاسازی
```

اگر رزرو نداشته باشی، در حراج دو نفر هم‌زمان آخرین موجودی را می‌خرند و فردا باید به یکی زنگ بزنی.

---

## ۲۰.۶ نگاشت دامنه به Tenant

```text
request host: myshop.com
  -> جستجو در کش نگاشت دامنه (Redis)
  -> اگر نبود، جستجو در جدول tenant_domains
  -> tenantId در request context
  -> هیچ هدری از کلاینت پذیرفته نمی‌شود
```

این نگاشت باید تقریباً همیشه از کش پاسخ داده شود. یک query دیتابیس به ازای هر درخواست فروشگاه، در مقیاس خودکشی است.

---

## ۲۰.۷ بودجه کارایی فروشگاه

| مسیر | هدف p95 |
| ------ | ---------- |
| صفحه محصول با cache hit | زیر ۱۰۰ms |
| صفحه محصول با cache miss | زیر ۵۰۰ms |
| لیست دسته | زیر ۳۰۰ms |
| افزودن به سبد | زیر ۲۰۰ms |
| ایجاد سفارش | زیر ۸۰۰ms |
| نرخ cache hit کاتالوگ | بالای ۹۰٪ |

---

## ۲۰.۸ جستجو

فاز ۲: Postgres با `tsvector` و ایندکس GIN. برای تا حدود ۵۰ هزار محصول در هر Tenant کافی است.

شرط مهاجرت به OpenSearch (تصمیم با عدد، نه با سلیقه):

- p95 جستجو از ۳۰۰ms رد کند، یا
- نیاز به facet پیچیده و رتبه‌بندی معنایی ایجاد شود

---

## ۲۰.۹ معیار پذیرش

- صفحه محصول فروشگاه فقط یک query به Read Model می‌زند
- تست: تغییر محصول در پنل، طی حداکثر ۳۰ ثانیه در فروشگاه دیده می‌شود
- تست: دو خرید همزمان روی آخرین موجودی فقط یکی موفق است
- تست: درخواست با هدر tenant جعلی در فروشگاه بی‌اثر است
- داشبورد نرخ cache hit و تأخیر پروجکشن وجود دارد
